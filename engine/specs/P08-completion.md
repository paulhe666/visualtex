# P08 completion — contained grids, multiline editing and virtual viewport

Status: isolated engine/sandbox P08 capability complete candidate. This document
records the implemented P08 state after actual Native/WASM, browser and physical
Windows IME acceptance. It does not switch the production VisualTeX editor, alter
Office wire/session contracts, or override the separate red P00 protection gate.

## Implemented environment model

One outer formula frame owns one EngineSession and one formula/document identity.
Contained mathematical lines never borrow or merge adjacent formula frames.
Grid/GridRow/cell/column identities are structural editor identities and are not
source offsets, DOM nodes, Office formula IDs or MathLive offsets.

Supported contained environments in this phase are:

- gathered: one centered mathematical column;
- matrix: rectangular authored rows/cells with independent row/cell/column IDs;
- cases: fixed two-column schema with one font-driven left brace;
- aligned, align and align*: paired alignment columns sharing explicit anchors.

Physical source newlines remain source trivia. Row separators and ampersands are
parsed only at the current environment scope; comments, escaped ampersands, text,
braced groups and nested environments do not split an outer grid. Unsupported
row-gap/placement options and implicit ragged-cell forms remain preserved source
with an explicit diagnostic instead of being normalized or guessed.

## Editing and identity behavior

Shift+Enter at a root mathematical boundary promotes a single formula to one
contained gathered environment. Further Shift+Enter commands operate in the
nearest supported current environment. Existing Matrix, Cases and Aligned never
receive a nested gathered wrapper merely to add a row.

Matrix supports real row/column insertion/deletion, cell navigation, empty cells,
identified rectangular selection, rectangular clear/paste, independent copy and
complete undo/redo. Cases keeps its two-column schema; ordinary Enter inside Cases
is an internal row command while outer formulas retain their host Enter action.
Aligned keeps paired shared anchors: right/left pair geometry comes from one core
layout constraint system, not CSS margins or separate editors. Interior row
splits/merges preserve corresponding columns and unaffected mathematical IDs.

Cross-cell range operations that cannot be represented by a valid identified
rectangle fail atomically. Clipboard fragments carry source and shape, never live
session/node IDs. Pasted descendants receive fresh IDs while destination cell,
column and environment identities survive when their structure survives.

IME composition has priority over grid commands. A pending native Windows preedit
cannot insert an environment row. Actual system-IME acceptance exercised guarded
Win32 SendInput ASCII pinyin and Shift+Enter in a UUID/PID-owned Edge window; it
used neither CDP imeSetComposition nor Unicode injection nor clipboard text.

## Layout and vector behavior

Grid layout is generated by the Rust core and consumed by one SVG view. Matrix
columns share measured widths; Cases is left aligned behind a real stretchable
math-font brace; Aligned pairs share explicit column anchors across every row.
Empty cells have real caret/hit positions. Selection overlays are editor paint only
and never enter exported SVG. Natural CSS-pixel geometry is independent of screen
zoom and devicePixelRatio.

The same LayoutSnapshot owns glyph positions, carets, hit regions, grid anchors and
SVG output. No DOM measurement decides mathematical alignment. Column anchor data
is explicit so P11 can later derive MathType ruler-stop compatibility without
reverse engineering SVG transforms.

## Long-document viewport ownership

A passive long-document viewport does not instantiate an editable input DOM for
every formula. EngineEditorSessionOwner separates core session ownership from the
mounted EngineEditorHost. Only nearby formulas own textarea/SVG host DOM.

The runtime supports bounded parkSession/resumeSession. Parking moves the exact
EngineSession out of the active map, drops layout/scene caches, and retains source,
NodeIds, selection, history, event receipts and the same handle. It does not rebuild
from LaTeX. Active sessions remain capped at 64. Parked sessions have an independent
count/weight budget. An active IME composition pins its formula and prevents park.
Destroy removes either active or parked state and releases all ownership.

A real Edge review scrolled through 1000 formulas. Every formula was materialized;
peak mounted hosts, textarea inputs, SVG views and active sessions were 11 each,
while 992 sessions were parked after the full scan. Returning to formula 0 kept the
same handle and exact editor snapshot, and undo/redo restored the same mathematical
IDs. Dispose returned active/parked sessions and editable DOM counts to zero.

## Stable acceptance gate

The qualifying P08 runner executes, on one unchanged source inventory:

1. full Rust workspace build/tests plus Native/WASM baseline parity;
2. Matrix/Cases/Aligned Native/WASM grid parity with fresh-parser oracles;
3. real Edge keyboard/pointer/zoom/DPR grid acceptance;
4. real browser rectangular clipboard acceptance;
5. real Edge 1000-formula virtual viewport acceptance;
6. physical Windows IME acceptance for Cases and Aligned;
7. gathered Native/WASM and two-frame browser acceptance;
8. host grid-boundary fault injection.

A PASS means each command actually executed. Earlier failed receipts remain in
unique target directories and are not rewritten: inline-script CSP rejection,
Windows foreground-lock rejection before any key was sent, intentionally too-strict
IME source assertions, wrong test identity baselines, and virtual-scroll fixture or
sampling mistakes all remain distinguishable from the final passing evidence.

## Phase boundary

P08 completion is limited to the isolated engine and sandbox host. The following
remain later phases and are not implied by this status:

- P09 command-input state, user macros/templates, versioned rich clipboard beyond
  the grid fragment capability, custom-symbol library integration and OCR target
  revision checks;
- P10 production main-app EngineHost/default switch and application persistence;
- P11 MathML/OfficeExportResult compatibility and MathType ruler-stop encoding;
- P12/P13 Office dialog/automatic-conversion integration;
- P15 removal of production MathLive/MathJax runtime dependencies;
- installed Word/PowerPoint Ribbon acceptance for the new engine.

P00 production/Office protection remains a separate gate. Parallel VSTO/evidence
changes in the dirty checkout are not changed, reverted or absorbed by P08.
