# VisualTeX macOS 项目方向与工程边界

> 本文取代早期“第一版 MVP”规划，是 macOS 端当前产品方向和功能优先级的长期说明。具体用户操作以 `docs/help/VisualTeX_帮助手册.md` 为准，Office 细节以 `docs/MACOS_OFFLINE_OFFICE_ARCHITECTURE.md` 为准。

## 1. 产品定位

VisualTeX 是面向 macOS 的本地数学公式编辑与 Office 集成应用。它以 MathLive 可视化编辑器和标准 LaTeX 为核心数据链路，同时提供：

- 可视化公式编辑、源码编辑、命令候选和公式工具栏；
- 公式磁贴、历史记录、快捷键和个性化设置；
- SVG、PNG、Markdown 等导出；
- 本地图片公式 OCR；
- Word 原生离线 DOTM 与 PowerPoint 原生离线 PPAM 集成；
- 图片公式、OMML、编号、交叉引用和双击编辑；
- 可编辑矢量自定义字符及 LaTeX 命令注册。

VisualTeX 不负责完整 LaTeX 文档编译，不捆绑 TeX Live，也不把 macOS Office 路线改回 Office.js。

## 2. 平台边界

macOS 功能只在 `apps/macos` 内实现。除非有明确的跨平台任务：

- 不修改 `apps/windows`；
- 不复用 Windows COM/OLE、VSTO 或 NSIS 逻辑；
- 不把 macOS 原生 Office 文件桥接改成在线 Web 插件；
- 不通过鼠标坐标、键盘模拟或界面语言匹配控制 Office；
- 不为解决 macOS 问题破坏 Windows 的独立构建和发布目录。

## 3. 当前核心架构

### 3.1 编辑器

- React + TypeScript 负责主界面和交互。
- MathLive 负责结构化公式编辑与光标模型。
- CodeMirror 负责 LaTeX 源码编辑。
- Zustand 和本地配置负责公式文档、偏好、历史和快捷键状态。

### 3.2 渲染与导出

- MathLive 负责编辑态显示。
- MathJax 与自定义兼容层负责 SVG、PNG 和 MathML 输出。
- 自定义字符必须在编辑态、预览、导出和 Office 图片公式中使用同一份矢量定义。
- OMML 无法表达自定义矢量字形时，使用用户明确设置的语义 fallback；不得悄悄替换成错误字符。

### 3.3 Office

- Word 使用 `VisualTeX.dotm`。
- PowerPoint 使用 `VisualTeX.ppam`。
- VBA 通过 AppleScriptTask 打开固定的 VisualTeX Session。
- 请求和结果只在 Office Group Container 中交换。
- 公式对象替换必须保持事务性，失败时保留原对象。

### 3.4 OCR

OCR 使用本地 PaddleOCR PP-FormulaNet sidecar。安装、模型缓存、识别和诊断都应在用户本机完成；网络只用于用户主动安装尚未具备的运行环境或模型。

## 4. 自定义字符系统目标

自定义字符不是独立绘图玩具，而是完整公式数据链路的一部分。一个注册字符需要同时满足：

1. 可以继续编辑其原始图层，而不是只保存扁平截图；
2. 可以在公式编辑器中通过 LaTeX 命令输入；
3. 可以出现在命令候选、磁贴和常用入口；
4. 公式复制、粘贴、历史恢复和 Office 重开后仍能解析；
5. SVG、PNG、Word 图片公式和 PowerPoint 图片公式保持相同矢量外观；
6. 删除或缺失定义时明确提示，不静默显示成其他字符；
7. 存储升级时不截断已有字符库。

## 5. 当前功能改进顺序

以下顺序来自用户提供的 7 页优化 PPT，应逐项实现和单独验收，不把多个高风险功能一次性混在一起。

### 5.1 字符库扩展、复用与素材入口

- 取消当前 96 个注册字符的产品级上限，改用可扩展、可迁移的持久化方案。
- 注册字符默认只进入自定义字符列表和命令候选，不自动加入“常用”磁贴；常用磁贴继续保持用户已有的固定内容。
- 公式复制粘贴后仍应保留自定义命令；在同一 VisualTeX 配置中无需重新注册。
- 字符设计器只提供可独立使用的裸字符和裸符号；分式、根式、矩阵、字体包装等复合公式模板不得从主公式工具栏直接照搬进来。

### 5.2 无边界画布与自动墨迹布局

- 中间工作区在视觉上采用可平移、可缩放的无边界画布，不显示固定纸张或输出框。
- 字符尺寸根据所有可见图层的实际墨迹、描边、旋转、裁剪和透视边界自动计算。
- 不同基线、高度和宽度的组合字符不得被固定画幅裁剪。
- 背景网格只能作为低对比度定位辅助，不能主导视觉，也不能进入导出。
- 点击图层后应直接显示类似 PowerPoint 的八方向缩放手柄和旋转手柄；角点默认等比缩放，且对角锚点不漂移。
- 自动边界不得破坏图层坐标、数学基线和用户手工裁剪；右侧仍保留位置、比例和角度等精确输入。

### 5.3 数学斜体保持

- 从 LaTeX 素材加入普通变量、希腊字母和扩展数学字形时，默认保持原数学字体的倾斜角和轮廓。
- 不把数学变量错误转成文本正体。
- 需要正体时由用户主动选择，而不是素材编译阶段统一强制。

### 5.4 翻转与中心旋转

- 支持水平翻转和垂直翻转。
- 支持任意角度旋转。
- 默认围绕图层自身视觉中心旋转和翻转，不围绕画布原点漂移。
- 所有变换必须可编辑、可持久化，并在运行时 SVG/PNG/Office 输出中一致。

### 5.5 智能空心描边

- 为字形提供真正的矢量空心效果，而不是简单叠加两条容易重糊的描边。
- 内外轮廓在不同字号和复杂形状下应保持相对均匀、闭合和流畅。
- 空心与实心字符并排时必须有清晰视觉区分。
- 输出不得依赖背景色遮盖，透明背景仍应正确。

### 5.6 透视效果

- 透视应作为非破坏效果保存参数，不直接丢弃原字形。
- 第一阶段只实现可预测的二维到三维挤出/透视；更高维概念不作为不明确的营销按钮直接加入。
- 透视结果必须在缩放、导出和透明背景下稳定，不能产生自交、断层或明显锯齿。

### 5.7 扩展符号库

- 素材选择器覆盖 VisualTeX 已支持的完整 LaTeX 命令和 Unicode 数学字符。
- 对 macOS 上可用的系统数学字体进行合规枚举和字形提取，优先支持 Cambria Math 可映射字符。
- 不把微软专有字体文件复制进仓库或安装包；缺少该字体时使用可公开分发的数学字体或 LaTeX 字形回退。
- 扩展字符必须经过命令冲突、字形边界、基线和导出兼容验证。

## 6. 验收原则

每个功能点至少验证：

- 新建、保存、重开和再次编辑；
- 主编辑器显示与设计器预览一致；
- LaTeX 源码不被改写成不可恢复的临时命令；
- SVG 与 PNG 透明背景正确；
- Word 和 PowerPoint 图片公式保持外观；
- 有 OMML fallback 时语义正确，无 fallback 时给出明确错误；
- 中文输入、MathLive 命令候选和普通公式不发生回归；
- 大量字符或复杂图层不会导致明显启动延迟。

## 7. 文档维护规则

长期文档只保存稳定的架构、操作和验收规则。以下内容不得继续写入仓库长期文档：

- 对话记录；
- 某一轮任务交接话术；
- 个人工作区绝对路径；
- 一次性 DMG、DOTM、PPAM 哈希；
- 已失效的功能分支名；
- 未实际执行却写成已经通过的测试结论。

阶段性构建结果应保存在被忽略的 `build-logs/` 或 `test-results/`，需要提交时使用版本化发布说明，而不是覆盖长期项目方向。
