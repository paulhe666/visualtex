# 编辑器候选框推荐逻辑：现状诊断与改造方案（2026-10-13）

范围：公式编辑器输入 `\xxx` 时弹出的命令候选框（MathLive 内核 `suggest()` + VisualTeX 目录）。
本文件只讲**排序/推荐**；编号选择、行重叠、问号/空白预览已在同日修复（见文末“已完成”）。

---

## 1. 现状诊断（有实测证据）

排序实现：`apps/windows/vite.mathliveSemanticCompletion.ts` 里注入内核的 `suggest()`；
另有一套独立的 `src/autocomplete/CommandSearchEngine.ts`（CoreMathEditor / CommandSuggestionPopup 使用），两套常数不同、逻辑不同。

### 1.1 分数量纲混乱、靠硬编码兜底

| 信号 | 分值 |
|---|---|
| 大小写完全一致 | 5000 |
| “家族”硬编码（int/sum/lim/frac 系列） | 900 − 25×位次，**直接覆盖**其它所有分数 |
| 忽略大小写一致 | 760 |
| 关键词完全一致 | 600 |
| 命令前缀 | 470 − 长度差 |
| 原生 MathLive 符号前缀 | 445 − 长度差 |
| 关键词前缀 | 450 − 长度差 |
| 个性化 | 最高约 905（终身 180 + 前缀 140 + 近期 420 + 最近一次 45 + 置顶 160） |

各项是“拍脑袋”的加法，彼此不在一个尺度上：一次近期使用（2 分钟内 +95，再加最近一次 +45）就足以越过几十分的前缀差距；家族硬编码又把这一切盖掉。

### 1.2 没有“常用度”先验 → 首选经常不对

无使用记录时（`usage = {}`）实测的前几位（`.cache/candidate-audit-before.json`）：

| 输入 | 当前前几位 | 中学/大学数学里期望 |
|---|---|---|
| `\i` | `\in` `\it` `\int`… | `\int` `\infty` `\in` |
| `\s` | `\sf` `\sum`×5 … | `\sum` `\sin` `\sqrt` `\sigma` |
| `\b` | `\bm` `\bf` `\bra` `\Box` | `\beta` `\bar` `\because` |
| `\c` | `\c`（软音符!）`\cos` `\cap` | `\cos` `\cdot` `\cap` `\cup` |
| `\d` | `\dd` `\dv`（physics 宏包）`\div` | `\delta` `\div` `\dots` `\dfrac` |
| `\v` | `\vb` `\va` `\vu` `\vec` | `\vec` `\varphi` `\vee` |
| `\r` | `\rm` `\rho` `\rVert` | `\rho` `\rightarrow` |
| `\t` | `\to` `\tt` `\tan` | `\times` `\to` `\tan` `\theta` |
| `\e` | `\exp` `\eta` `\erf` | `\epsilon` `\exp` `\eta` |

原因：同等匹配下只按“名字越短越前”排，偏爱 2 字母的冷门命令（`\c` `\dd` `\vb` `\rm` `\tt`）。

### 1.3 关键词泄漏

关键词/别名匹配没有边界控制：`\ph` 出 `\bra` `\ket` `\braket`，`\fo` 出 `\parallelslant`，`\fi` 出 `\sum` `\prod` `\varsigma`，`\ra` 首位是 `\operatorname{rank}`。

### 1.4 同名多变体，标签相同

`\sum` 有 5 个条目、`\int` 6 个、`\begin{bmatrix}` 7 个、`\iint`/`\iiint` 各 6 个。候选框里连续出现 5 行 `\sum`，只能靠预览区分，还挤掉了其它候选。

### 1.5 个性化会让列表“跳”

数字键测试中观察到：每次采纳都会写 usage，下一次输入同一前缀时列表顺序就变了。这对“按数字选”的肌肉记忆是致命的——输入法的核心体验就是同一编码的位置稳定。

### 1.6 学习信号太窄

- `acceptedPrefixes` 只记录采纳那一刻的完整查询（`su`），之后输入 `s` 得不到任何加成。
- `contextCounts` 只记来源（candidate/toolbar），不是上下文。
- 只记“选了谁”，不记“展示了什么、跳过了谁”，无法评估也无法学习。
- 没有离线评估基准，改动好坏只能凭感觉。

## 2. 成熟系统怎么做（调研）

| 系统 | 做法 | 可借鉴点 |
|---|---|---|
| **Rime / librime 输入法** | 用户词典记录词频与“tick”（提交计数器），权重按 `d + da·exp((ta − t)/200)` 随提交次数指数衰减（`src/rime/algo/dynamics.h`），再与词库先验合成概率 | 用**提交次数**而不是墙钟时间做衰减；先验 + 用户频率在**概率空间**合成 |
| **VS Code IntelliSense** | 排序 = 模糊匹配分 + 提供方 sortText；`editor.suggestSelection: recentlyUsedByPrefix` 按“已输入前缀”记住上次选择，只改变**预选项**，不打乱列表 | “排序”和“预选”分离：列表稳定、高亮跟着习惯走 |
| **JetBrains IDE** | 用匿名使用日志训练 CatBoost 排序模型，A/B 测试中完成一次补全所需按键从 2.073 降到 1.832（ESEC/FSE 2022 “All You Need Is Logs”） | 先有展示/选择日志，再谈学习；指标用“按键数” |
| **Firefox frecency** | 每次访问按类型分桶加权 × 指数衰减（半衰期 30 天），取最近 N 次的平均 × 总次数 | 频率与近因合成的标准公式；半衰期以“天”计，不是分钟 |
| **Overleaf** | 原先 Fuse.js 模糊搜索不考虑常用度（`\c` 首位是 `\columnbreak`），改为统计约 8000 篇公开文档的命令频率做排序 | 与我们 `\c`→软音符完全同类问题；**语料先验**是第一优先级 |
| **Writefull arXiv 统计** | 30 万篇论文的命令频率表 | 通用数学先验来源 |
| **无偏排序学习**（Joachims 等 2017）| 点击受位置偏差影响，需用倾向性加权；“跳过”的候选作为负例要谨慎 | 第三阶段学习权重时使用 |

共同结论：
1. **先验常用度**是基础（Overleaf、输入法词库）；
2. **用户频率+衰减**在概率空间与先验合成（librime、Firefox）；
3. **位置稳定性**单独处理（输入法、VS Code 只改预选）；
4. 有了日志和离线指标之后，才用学习方法调权重（JetBrains）。

## 3. 目标与验收指标

| 指标 | 定义 | 目标 |
|---|---|---|
| Top-1 命中率 | 真实/模拟会话中，第一候选就是要的命令 | 较基线 +15pp |
| MRR | 目标命令名次倒数的平均 | 较基线 +0.1 |
| 平均按键数 | 从 `\` 开始到提交（含数字键/空格）所需按键 | 较基线 −20% |
| 列表稳定性 | 同一前缀相邻两次展示的前 9 位 Kendall τ | ≥ 0.9（个性化开启时） |
| 延迟 | 每次按键排序耗时（≈1500 条目） | < 2 ms |

基线由第 6 节的评估工具在改造前先跑出来。

## 4. 目标架构

```
按键 → 召回(recall) → 特征 → 打分(log-linear) → 分组/去重 → 稳定化 → 分页编号展示
                                               ↑
                             先验(语料) + 用户模型(衰减频率) + 上下文
```

### 4.1 召回：统一目录 + 分级匹配

- **一个目录**：VisualTeX 命令表 + MathLive 原生符号 + 用户宏 + 自定义符号，统一成 `{id, trigger, template, preview, labels, aliases, keywords, pinyin}`。两套排序器合并为 `src/autocomplete/ranking/`（纯 TS、可单测），内核 `suggest()` 只调用它。
- **匹配类型**（每条只取最好的一种）：
  1. 大小写一致的完整命令；
  2. 忽略大小写的完整命令；
  3. 命令前缀；
  4. 词段前缀（`\lra`→`\leftrightarrow`、`\ola`→`\overleftarrow`，按驼峰/单词边界切分）；
  5. 别名/英文关键词的**词首**前缀，且要求查询 ≥3 字符（修 1.3 的泄漏）；
  6. 中文标签的**拼音全拼/首字母**（`\jf`→积分，`\qh`→求和），可开关；
  7. 模糊（查询 ≥4 时编辑距离 ≤1）。

### 4.2 打分：同一尺度的对数线性模型

```
score(c | q, ctx) = w_m · match(q, c)            // 匹配类型分（离散表，见 4.1）
                  + log P_prior(c)               // 语料常用度
                  + w_u · log P_user(c | q)      // 用户模型（下式）
                  + w_x · log P_ctx(c | ctx)     // 上下文
                  − w_len · lengthPenalty(c, q)  // 只作为微弱的平局打破
```

- **先验 P_prior**：语料计数 + 加法平滑。语料 = 用户自己的 Word 试卷（中学数学/物理，权重 0.7）+ arXiv 通用频率（0.3）。physics 宏包这类冷门命令自然沉底，`\c` 软音符不会再排第一。
- **用户模型 P_user**：沿用 librime 思路，以“提交次数”做衰减（与日历时间无关、离开几天回来不会突变），再与先验做贝叶斯平滑：
  `P_user(c|q) = (Σ_k decay(tick−t_k) · [q ⊑ q_k] + α·P_prior(c)) / (N_q + α)`
  其中 `q ⊑ q_k` 表示本次查询是当时查询的前缀——采纳 `\sum` 时 `s`、`su`、`sum` 三个前缀都记一次（越短权重越低），修 1.6。
- **置顶**：用户显式置顶的条目固定在首位（输入法“固顶”）。

### 4.3 上下文 P_ctx

- **前一命令二元组**：`\int` 之后 `\mathrm{d}`，`\lim` 之后 `\to`/`\infty`，`\left(` 之后 `\right)`。来源同样是语料 + 用户。
- **结构位置**：在上下标里提升 `\infty` `\to` `\prime`；在矩阵/数组里提升 `\cdots` `\vdots` `\ddots`；在 `\text{}` 里只给文本命令。
- **文档缓存**：当前文档里已出现的命令加分（输入法“会话词频”）。

### 4.4 变体分组

同一 trigger 的多个模板（`\sum` 的 5 种、`\int` 的 6 种、矩阵 7 种）合并为**一行**，显示最可能的变体；需要其它变体时：
- 方案 A：行内右侧小箭头 / `Tab` 展开二级列表；
- 方案 B：不分组，但在行尾显示中文短标签（“有限和”“级数”“不定积分”）区分。
推荐 A（列表更短，编号更有价值），B 作为过渡。

### 4.5 稳定化（对“按数字选”最重要）

- **滞后阈值**：同一前缀下，新候选的分数必须超过当前首位一个固定差值才能换首位。
- **会话内冻结**：一次编辑会话中，同一前缀的前 9 位顺序最多变一次。
- **排序与预选分离**（VS Code 做法）：短期习惯只移动高亮（预选项），不打乱编号；长期频率才影响顺序。

### 4.6 反馈采集（本地，不上传）

环形缓冲（约 5000 条）记录：查询、展示的前 9 位、采纳位次与方式（数字/空格/回车/鼠标）、上下文签名、时间。用途：离线评估、拟合权重、计算稳定性指标。设置页提供“清除学习数据”。

### 4.7 学习（第三阶段）

用日志做成对逻辑回归（采纳项 > 排在其上方的跳过项），用位置倾向性加权纠偏（Joachims 2017），只学 4.2 里的少量权重 `w_*`。数据足够之后再考虑 GBDT（JetBrains 路线）。

## 5. 先验语料构建

1. 收集用户已有的 Word 试卷/讲义（OMML 和 MathType 都有现成的 LaTeX 转换器），批量导出 LaTeX；
2. 统计命令出现次数、模板形态（`\sum_{i=1}^{n}` 归入 `sum` 变体）、前一命令二元组；
3. 合并 arXiv 通用频率表；
4. 生成 `src/autocomplete/ranking/commandPrior.json`（命令 → 计数、变体分布、二元组），构建期打包；
5. 目录中语料里从未出现的命令取最小平滑值。

## 6. 评估工具（先做，用来量基线）

- **模拟回放**：从语料的每个命令出现位置，模拟输入前缀 k = 1…n，记录目标名次 → Top-1、MRR、平均按键数。
- **真实回放**：用 4.6 的日志重放。
- **回归门禁**：
  - 黄金用例，例如 `\i` 前 2 位含 `\int`、`\s` 首位 `\sum`、`\c` 前 3 位不含 `\c`、`\ph` 不出现 `\bra`；
  - `scripts/candidate_panel_audit.mjs --sweep`（版面/缺字形/问号全量扫描）；
  - `--digits`（编号选择）。

## 8. 风险

- **肌肉记忆**：排序大改会让老用户“找不到”。对策：P0 起就加稳定化；发版说明；保留置顶。
- **语料偏差**：试卷以中学为主，大学/物理用户可能不适配。对策：先验只占一部分，用户模型很快接管；必要时提供学科配置（数学/物理/通用）。
- **数字键与输入数字冲突**：在候选框打开时数字被当作选择（与输入法一致）；需要输入 `\frac12` 这类紧凑写法时，先按 Esc 关闭候选框。
- **性能**：1500 条 × 每键，拼音与模糊匹配需预计算索引，保证 < 2 ms。

## 9. 需要你拍板的点

1. 变体分组：A（二级列表）还是 B（中文短标签）？
2. 是否加入拼音/首字母检索？
3. 语料：能否使用你现有的试卷文档统计常用度（只在本地处理，产出计数表）？
4. 个性化默认强度：偏“稳定”（只改预选）还是偏“自适应”（允许改顺序）？

## 已完成（同日）

- **数字键选择**：候选按 9 个一页编号 1–9，数字键直接提交（与空格提交同一路径）；方向键翻到下一页时编号跟着换页；超出本页的数字被吞掉；候选框关闭时数字照常输入。
- **行重叠**：根因是候选列表为限高 flex 纵列，行默认 `flex-shrink: 1`，滚动时所有行被压到 48px 最小高度，`\sum` 带上下限（约 62px）、矩阵、`cases` 溢出盖住相邻行。改为 `flex: 0 0 auto`，行高随内容。
- **模板当命令名**：三行 `cases`、省略号/对角/分块矩阵、带限大运算符等条目把整段模板当作命令名，标签超出右边界；改为取首个控制序列作为命令名。
- **鼠标点击模板候选无效**：可见层按“命令名”去找源条目，而源条目以插入模板为键，已改为按插入模板匹配。
- **候选可见层与内核不一致**：原先可见层对 ≥4 字符的查询再次过滤，导致编号/索引与内核错位；过滤移入内核 `suggest()`，两边一一对应。
